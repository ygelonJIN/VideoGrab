# 视频下载器 · 使用说明

**什么时候读**：改嗅探逻辑、改下载调度、动 aria2 / 助手接口、加新的下载后端、Chrome 升级后扩展失效。

---

## 架构与数据流

```
页面请求
  └─ webRequest.onBeforeSendHeaders ──► 暂存 Referer / UA / Cookie / Origin（按 requestId）
  └─ webRequest.onHeadersReceived ────► 认媒体类型 + Content-Length + Accept-Ranges
                                        └─► tabItems[tabId] ──► storage.session（防 SW 休眠丢数据）
                                                │
popup 读列表 ◄──────────────────────────────────┘
   │
   ├─ ⚡ aria2：background 组 options.header ──► aria2 JSON-RPC addUri
   ├─ ⬇ 浏览器：chrome.downloads（不支持自定义头，只适合没防盗链的）
   ├─ 解析：先请助手 fetch（能带 Referer），失败再扩展自己 fetch
   └─ 助手：POST /api/jobs ──► ffmpeg（HLS）或 aria2c（MP4），轮询 /api/jobs 看进度
```

三个存储位置：

| 位置 | 存什么 | 生命周期 |
|---|---|---|
| `tabItems`（内存 Map） | 当前标签页的媒体列表 | SW 休眠后靠 session 恢复 |
| `chrome.storage.session` | `tab:<tabId>` → {items, segCount} | 关浏览器即清 |
| `chrome.storage.local` | `settings`、`jobs`（aria2 gid 列表） | 长期 |

## 请求头从哪来（403 的关键）

顺序是 `onBeforeRequest → onBeforeSendHeaders → onHeadersReceived`，同一个 `requestId` 串起来：

1. `onBeforeSendHeaders` 里把四个头按 `requestId` 存进 `pending`；
2. `onHeadersReceived` 判出是媒体后，把 `pending` 里的头合并进条目；
3. `onCompleted` / `onErrorOccurred` 清掉 `pending`，并做容量截断（超 3000 条砍一半）。

**必须带 `extraHeaders`**：不写这个参数，Chrome 不会把 `Cookie`、`Referer` 交给监听器。

```js
chrome.webRequest.onBeforeSendHeaders.addListener(fn, { urls: ['<all_urls>'] }, ['requestHeaders', 'extraHeaders']);
chrome.webRequest.onHeadersReceived.addListener(fn, { urls: ['<all_urls>'] }, ['responseHeaders', 'extraHeaders']);
```

另外 `manifest` 的 `host_permissions` 必须是 `<all_urls>`，否则只有当前激活标签页的权限。

## aria2 接口约定

- 方法 `aria2.addUri`，参数顺序 **`[token, [url], options]`**（token 形如 `token:密钥`，没设密钥就是 `token:`）。
- `options.header` 是**字符串数组**：`['Referer: https://x/', 'Cookie: a=b', 'User-Agent: ...']`，不是对象。
- 多线程三件套：`max-connection-per-server`（-x）、`split`（-s）、`min-split-size`（-k）。
- 断点续传靠 `continue=true`，同时要写控制文件（默认同目录 `.aria2`），所以 `-o` 名字别乱改。
- 只支持 http/https/ftp，**不支持 m3u8**；HLS 必须走 ffmpeg。

`aria2InputText()` 生成的导出文件长这样，可直接 `aria2c -i 文件`：

```
https://cdn/x.mp4?sig=1
  dir=/Users/xx/Downloads
  out=x.mp4
  max-connection-per-server=16
  split=16
  header=Referer: https://site/watch
  header=Cookie: a=b
```

## 助手接口

只绑 `127.0.0.1:8765`（`VG_PORT` 可改）。无依赖，Node 18+ 直接跑。

| 方法 | 路径 | body / 返回 |
|---|---|---|
| GET | `/api/health` | `{ok, ffmpeg, aria2c, curl, ffmpegPath, defaultOut}` |
| POST | `/api/parse` | `{url, headers}` → `{status, text}`；解析播放列表用，能带 Referer |
| POST | `/api/jobs` | `{type:'hls'\|'mp4', url, name, headers, outDir}` → job |
| GET | `/api/jobs` | `{jobs:[...], running, queued}` |
| POST | `/api/jobs/:id/cancel` | 取消 |
| GET | `/api/jobs/:id/log` | ffmpeg/aria2c 输出尾部 |
| POST | `/api/probe` | `{url, headers, proxy}` → `{ok, media:{duration,width,height,videoCodec,audioCodec,size,source}}`；MP4 走头部解析，HLS 直接返回空（前端用播放列表） |
| POST | `/api/scan` | `{url, links?, headers?, proxy}` → `{source:'html'\|'dom', title, media, listing, total}`；列表页用，`links` 是扩展从 DOM 抠出来的链接 |
| POST | `/api/resolve` | `{url}` 或 `{urls:[≤20]}` → `{ok, gone, unavailable, media:{url,kind,size,headers,headerMode}, reason, steps}`；`media.headers` 是**验证过能用**的那套头 |
| POST | `/api/files/exists` | `{paths:[≤50]}` → `{exists:{路径: true\|false\|null}}`；只回答 home 和 `/Volumes` 下的路径，其余给 `null`（不明确回答） |

`headers` 对象字段固定为 `{referer, ua, origin, cookie}`，和扩展里的 item.headers 一致。

type 判断：

- `hls` → ffmpeg，参数固定在 `ffmpegArgs()`：
  `-protocol_whitelist file,http,https,tcp,tls,crypto -allowed_extensions ALL -allowed_segment_extensions ALL -extension_picky 0`，全部在 `-i` **之前**。
- `mp4` → 有 `aria2c` 用 aria2c（`-x16 -s16 -k1M --continue`），没有就 `curl -f -L -C -`。

进度：

- HLS 从 ffmpeg stderr 抓 `Duration:` 和 `time=` 算百分比；
- MP4 每 900ms stat 输出文件，跟 `Content-Length` 比；长度先 HEAD 探，失败再 `Range: bytes=0-0`。

并发上限 `VG_CONCURRENCY`（默认 2），超出排队。

## 批量抓取（通用发现器）

**目标**：在列表页一屏抓完，不点开任何视频 —— 也就不会触发"点一下弹广告、跳新标签"。

### 为什么不能靠嗅探

两道断点，都是结构性的，不是 bug：

1. 列表卡片通常是 `<video preload="none">`，只挂 poster 和预览片，**不 hover 就不发任何媒体请求**；
2. 正片在跨域 `<iframe>` 的播放器里，不点播放同样零请求。

所以"在列表页嗅探"永远是空的。真正的做法是**解析页面结构拿地址**，不是等请求。

### 三个发现器，引擎里不写站点名

`helper/extract.mjs` 全是纯函数，只按特征识别：

| 发现器 | 认什么 |
|---|---|
| 直出 | `<video src>` / `<source src>` / `og:video` / JSON-LD `contentUrl` |
| 打包 | `eval(function(p,a,c,k,e,d){...})` 解开后找 `wurl` / `file` / `src` 之类字段 |
| 嵌入 | `<iframe src>` 指向播放器（`/e/`、`/embed/`、`/player`），再钻一层重跑前两个 |

列表页另有一条：**两级分组**（`groupDomLinks()` / 扩展侧 `groupListing()`，两边保持一致，selftest 对照）：

1. **路径模板**（`/watch/123` 抹成 `/watch/:id`，2 位以上数字、uuid、长 hex 都算 id），同模板重复 ≥3 次就是条目列表；
2. **目录兜底**：模板组没认领的链接里，同一父目录下的不同子路径 ≥3 条也算（slug / 标题型列表页，如 `/videos/episode-one`）。
   根目录不做兜底 —— 导航链接全挤在根上，兜了必认错。

噪音要在分组前滤掉：导航页（`NAV_HINT`）、静态资源（`.css` / 图片 / 字体）、翻页排序（`?page=` 等）。

要支持新站，先看它属于哪类；三类都套不上才加站点规则。别一上来就写 `if (host === 'xxx')`。

### 请求头：两件事必须做对

1. **UA 必须是浏览器的**。`curlRange()` 现在统一兜底 `DEFAULT_UA` —— 实测不带 UA 的请求被 CDN 直接 403，而 curl 默认 UA 是 `curl/x.y`。
2. **Referer 有两种相反的极性**。有的站防盗链（必须带），有的站反过来（带了就 403）。所以 `probeMedia()` 带/不带各试一次，把**能过的那套头**写进 `media.headers` 返回；下载端照抄即可，不要在下载侧再猜一遍。

### 三种结果，别混成一个"失败"

- `ok:true` — 拿到可下地址
- `gone:true` — 页面 404/410，或正文明确写 removed/deleted
- `unavailable:true` — 页面 200 但播放器里没有媒体配置（**托管端把文件删了**）

`unavailable` 是批量里最常见的（实测一个 20 条的老列表只有 3 条还有源）。UI 必须分开显示，否则用户会以为自己操作错了。

### 扩展侧流程

```
popup「批量」→ background batch:scan
  └─ chrome.scripting.executeScript 注入 collectPageLinks（读 DOM 链接 + 锚文本标签，allFrames 收 iframe）
  └─ POST /api/scan {url, links} → 两级分组，取最大的一组
  └─ 助手不通 → 退回 common.js 的 groupListing()（纯函数，只看链接结构）照样列条目
扫描完自动开始解析：batch:resolve（每 5 条一批，批间持久化一次，弹窗关了不丢结果；后台那边仍是每批 10 条）
popup「加入队列」→ batch:submit → POST /api/jobs，头用 media.headers
```

**给助手传链接必须是纯字符串数组**（坑 29）；标签由扩展侧回填，别指望助手带回。
弹窗侧还要自己加「≥3 条才算一组」的下限，老版助手会把单条链接也塞进 listing。

**助手不在线时的边界**：扫条目、复制链接、导出链接都能干（本地分组不联网）；
解析直链和下载必须有助手（解析要带 Referer 从页面外抓，扩展自己设不了，见坑 4）。
这时 UI 给引导卡 + 四步弹层，不要只丢一句报错。

**解析会断，必须能续**：解析跑在弹窗里，Chrome 弹窗一点外面就关。所以：

- 每批结果立刻落 `storage.session`（连勾选一起存）；
- 重开弹窗看到「待解析」就自动续解析，按钮文案跟着剩余条目走（`解析剩余 N 条` / `重试失败 N 条`）；
- 单条解析失败只标那一批，不中断后面的批次；助手掉了才整体停，停下来给引导。

**勾选语义**：解析出「可下」默认自动勾上（省事），但用户手动改过勾选之后就不再自动勾
（不然刚取消的会被后面解析出来的又带上去）。全选框要有半选态。单条勾选原地更新，别整表重建。

**列表页必须走 DOM**：懒加载的列表页 HTML 里一个条目都没有，`/api/scan` 只传 `url` 会返回空；`source:'dom'` 才说明链接是从页面读来的。

### 本地文件状态

**两条下载路径都要查**，漏一条就会出现"明明删了还显示已完成"：

- 助手任务：`publicJob()` 对已结束的任务直接带 `exists`（`fs.existsSync`）；
- aria2 任务：aria2 只知道下完了，所以要 `aria2:status` 收完状态后，把 `files[0].path` 批量丢给 `/api/files/exists` 补一个 `exists`。

查不到时（助手没开、太旧、路径不在白名单）就**保持未知**，别猜成"已删除"。
UI 见到 `exists === false` 才切「文件已删除」样式并去掉绿条。

直链会过期，重下要回批量页重新解析，不能直接续旧链接。

## 坑

### 1. 品牌版 Chrome 不能命令行侧载扩展

`--load-extension` 和 `--disable-extensions-except` 在 Google Chrome 137+ 被禁（日志会写 `not allowed in Google Chrome, ignoring`），headless 下扩展也不会注册。所以：

- 自测只能静态 + jsdom；
- 真浏览器验证要 `chrome://extensions` 手动「加载已解压」；
- 想用 `tools/cdp-test.mjs` 跑自动化，得装 Chromium / Chrome for Testing，不能用品牌版。

### 2. `extraHeaders` 漏了就拿不到 Cookie

只写 `['requestHeaders']` 时 `Cookie`、`Referer` 是空的，表现为"抓到了链接但 403"。改监听器时先查这个。

### 3. `.ts` 是双关

既可能是 TypeScript 源文件，也可能是 HLS 分片。`classify()` 里对 `.ts`/`.m4s` 要求 content-type 是 `video/mp2t`、`video/iso.segment`、`application/octet-stream` 或 `video/*`；命中不了就当普通文件忽略。别图省事只按后缀认。

### 4. 扩展自己的 fetch 设不了 Referer

`Referer` 是 forbidden header，SW 里 `fetch(url,{headers:{Referer}})` 会被静默丢掉。所以：

- 解析 m3u8 优先走助手的 `/api/parse`（助手是 Node，随便设头）；
- 助手不在线才退回扩展直连，此时对防盗链站点可能 403，UI 要给出"启动助手"的提示。

### 5. `chrome.downloads` 不支持自定义请求头

防盗链直链用浏览器下载必 403。`⬇` 按钮只适合没防护的资源；有防护的一律 `⚡` 或助手。

### 6. ffmpeg 的 `-headers` 用 `\r\n` 分隔

不是 `\n`。写成 `\n` 时 ffmpeg 只认第一行，后面的 Cookie 全丢。

### 7. `+faststart` 会让大文件结尾重写一遍

`-movflags +faststart` 要读完整个文件再写第二遍，1.3 GB 会白等几分钟。助手默认不开启，需要时设 `VG_FASTSTART=1`。

### 8. SW 会休眠，内存状态要落 session

`tabItems` 是内存 Map，MV3 的 service worker 几十秒没事件就被回收。所以每次新增条目都 debounce 写 `storage.session`，popup 读不到时从 session 恢复。别把状态只放内存。

### 9. 分片会刷屏

一集 HLS 有几百个 `.ts`，全列出来没法用。默认折叠，只记 `segCount`；设置里 `showSegments` 才显示。

### 10. Homebrew 从 ghcr 拉包在国内几乎停滞

`brew install aria2` 卡在下载时，换镜像：

```bash
export HOMEBREW_API_DOMAIN="https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles/api"
export HOMEBREW_BOTTLE_DOMAIN="https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles"
brew install aria2
```

### 11. HLS 专用参数喂给 MP4 会直接报错

`-allowed_extensions` / `-allowed_segment_extensions` / `-extension_picky` 是 HLS 解复用器的选项。
拿这套参数去开一个 `.mp4`，ffmpeg 会报 `Option not found`，整条命令失败。

所以助手的探针按 URL 猜类型，先试不带 HLS 参数的一轮，失败再换另一套；两套都试不通才报错。
`inputOpts(headers, hls)` 的第二个参数就是干这个的，别写死。

### 12. 详情不做缩略图，只读文件头

最初做过"ffmpeg 抓一帧当缩略图"，实测走代理要 41 秒，删掉了。原因不在数据量——
把 `-probesize` 压到 32 KB，ffprobe 还要 25 秒，它在这条链路上会来回请求十几次。

现在 MP4 走自解析：`curl -r 0-262143` 取开头 256 KB（一次请求，约 2 秒），
自己 walk box：`ftyp → moov → mvhd` 拿时长、`trak → tkhd` 拿宽高、`stbl → stsd` 拿编码。
实测 41 秒 → **4 秒**。

两个关键实现点：

- **box 可能比抓到的窗口还长**（moov 几 MB 很常见）。不能因为 `off + size > end` 就 return，
  要按可见部分继续 visit 和向下递归，否则只能看到 `ftyp`。
- **HLS 完全不联网**：时长 = `#EXTINF` 求和、清晰度来主播放列表，前端 `hls:parse` 已经有这些数据。

头里没有 moov（非 faststart）时，再取尾部 512 KB 找一次；再失败才退回 ffprobe（慢，但兜底）。

### 13. 扩展自己的 fetch 设不了 Referer

`Referer` 是 forbidden header，SW 里 `fetch(url,{headers:{Referer}})` 会被静默丢掉。所以解析播放列表
优先走助手的 `/api/parse`（Node 里随便设头），助手不在线才退回扩展直连，此时对防盗链站点可能 403。

### 14.5 删除文件的接口必须做双保险

`/api/file/delete` 能删磁盘文件，而助手对任何本机网页开放（CORS `*`），这是个现成的删文件漏洞。

两道闸：

1. **Origin 白名单**：带 `Origin` 且不是 `chrome-extension://` 开头的，一律 403。
   浏览器的 Origin 由浏览器写，网页伪造不了；curl 这类没有 Origin 的本地脚本放行。
2. **目录白名单**：`path.resolve` 后必须落在 `~/Desktop`、`~/Downloads`、`~/Movies` 之下，
   且带正常扩展名。`/etc/hosts` 这种会被直接拒。

顺带删掉同名的 `.aria2` 控制文件，否则下次下载会以为还有断点。

### 14.6 任务按钮按状态给，别一套到底

- `active/waiting` → 暂停、取消
- `paused` → 继续、取消
- `complete/error` → 删除文件、删除记录

"删除记录"只清 `chrome.storage.local` 里的 jobs 数组（aria2 侧再调 `removeDownloadResult`），
文件不动；"删除文件"先打助手接口再清记录。已完成的行加 `.done` 类，名称转灰、进度条转绿。

### 14.7 批量删除：先攒成一条消息，别在弹窗里循环

单条删除走 `file:delete` / `job:forget`，批量再那样写就是 N 次消息 + N 次 storage 读改写。
现在是 `jobs:cancel-many` / `job:forget-many` / `file:delete-many` 三条，弹窗只发一次：

- 参数形状：`{gids, ids}`（aria2 用 gid、助手用 id，一次消息带两边）和 `{paths}`；
  后台 `asList()` 负责去重、去空、限额（任务 100、文件 200），别信前端传多少就处理多少。
- **勾选不限状态，按钮按状态给**：勾中 `running` 的只开「取消所选」，
  勾中已结束的才开「删除记录 / 删除文件」；混着勾就只处理各自能处理的那部分。
- 删文件的记录清理**只对删成功的路径**（后台回 `deletedPaths`），失败的行留着，别把列表清空了文件还在。
- 批量删文件前先 `POST /api/health` 探一次。不探的话助手没开时，200 个路径每个都要等满 10 秒超时。

两个 UI 坑：

1. **任务列表每秒重建**（`refreshJobs` 在 `tick()` 里）。勾选状态只能放 state，
   渲染时按 key 回填；另外给列表算一个内容签名，没变就不重排 DOM —— 否则每秒闪一下，
   正点的勾选框会被换掉。
2. 「全选」和逐行勾选要同步 DOM，不能只等下一次刷新：否则在两次刷新之间连点会丢选择。

### 15. 签名链接可能绑定出口 IP，代理要一路到底

典型现象：**浏览器能播、能下，curl/ffmpeg 一律 403，但同一域名根路径返回 200。**
这不是防盗链头没带对，是签名里的 `s` 绑了请求时的出口 IP。

判定方法：同一条 URL、同一套头，只用 `curl -x http://127.0.0.1:7897` 加不加代理各试一次。
一个 206、一个 403，就实锤了。

后果：预览、aria2、ffmpeg 必须走**同一个**代理出口，否则永远 403；换节点后旧链接作废，
要回页面重新播放拿新链接。设置里的 `proxy` 字段就是分发给这三者的：aria2 用 `--all-proxy`，
ffmpeg/ffprobe 用 `http_proxy`/`https_proxy` 环境变量。

### 15.5 代理用「自动跟随系统」，不要写死地址

写死 `http://127.0.0.1:7897` 的问题：遇到能直连的站也会绕代理，白慢一截；用户关了代理软件，
aria2 还会往一个没人听的端口发请求。

现在 `proxyMode` 三档：`auto` / `off` / `manual`。`auto` 由助手读 `scutil --proxy` 拿
`HTTPEnable/HTTPProxy/HTTPPort`，再用 `nc -z` 确认端口真的在听，才返回地址。

两个细节：

- `scutil` 说开着、但代理软件已经退了 → 端口检测会把它判成 `system-http-dead`，按直连处理。
- 助手不在时 `auto` 退回手动地址（或空），保证 aria2 还能下能直连的站。

### 15.6 换出口 IP 前，先把「票」和「断点」分清楚

**什么时候读**：想换代理节点提速，或者换完之后任务同时大面积 403。

签名直链里 `s=…&e=…&_t=…` 的授权绑**签发时的出口 IP**。同一 IP 下什么都正常，一换节点，
在跑的和排队的会同时 403。这不是文件没了，是票作废。

- 判断方法：换节点后拿原链接发一个 1 KB Range 请求。`206/200` = 没绑 IP，任务会自己重连恢复；
  `403` = 绑了，必须回页面重新解析。
- 403 之后助手有「5 分钟一个字节都没收到就 kill」的保护，任务会被结束、进程退出。
  **`.mp4` 和 `.aria2` 都留着，进度不丢**，最多丢最后约 1 分钟（默认 60 秒自动保存）的分片记录。
- 换 IP 前先做三件事：把在跑和排队的任务停掉（否则每个都会 403，连失败还会留下空文件）；
  确认每个任务的 `.mp4` / `.aria2` 都在；把 `.aria2` 复制一份到别处（几百字节，纯保险）。

**续传必须同名**：

- 助手 `createJob()` 的 `taken()` 只在「同名 `.aria2` 存在、且 `jobs` 里没有同路径 owner」时放行原名。
- 旧任务即使已经 error，也还在 `jobs` 里，会触发改名成 `名字 (n).mp4`，从 0 开始下。
  顺序是：先 `POST /api/jobs/:id/forget` 清掉旧记录，再按原文件名提交新链接；
  或者干脆命令行 `aria2c --continue --out "原名" 新链接`。
- 别删 `.aria2`、别改名。这两条是唯一真正会丢进度的动作。

### 15.7 速度掉到几 KB 时，按这个顺序分锅

**什么时候读**：下载中途变慢，怀疑是代理、CDN 还是自己设置的问题。

四步，全部只读，不动任务：

1. 同一条代理下测 Cloudflare 1 MB（`speed.cloudflare.com/__down?bytes=1048576`）。
   能到 MB/s 级 → 代理链路没问题，别再折腾代理。
2. 看 aria2 日志里有没有 429/503/timeout/`errorCode`。一条都没有 → 不是被拒绝，是被**限速**
   （服务器在不报错地慢慢吐）。
3. 用 64 KB Range 测同一条链接的 TTFB 和吞吐，再跟另一个任务的子域对比。
   同一个 CDN 的不同子域能差 3～10 倍，说明差别在**边缘节点**。
4. 看时间点和累计量：前半小时 200 KB/s、累计几百 MB 后掉到几十 KB/s，**而且新开的任务一样慢**
   → 不是单节点，是 CDN 对**这个出口 IP** 的限速/配额。

对策按代价排：

- 提高 `-x/-s` 没用：限速按 IP 总量算，加连接只会让每条更慢。
- 只重新解析没用：出口 IP 没变，换了票还是同一档限速。
- 换节点才有用，但先按 15.6 判断票是否绑 IP；绑的话换完必须重新解析 + 同名续传，已下部分能接上。
- 判断「加连接不叠加」要小心：aria2 正在跑时，探测请求是在跟它抢同一份配额，
  测出来的「不叠加」不能当结论；要干净结论得在任务停掉时测。

### 16. 走代理时 ffmpeg 需要 httpproxy 白名单

`-protocol_whitelist file,http,https,tcp,tls,crypto` 里没有 `httpproxy` 时，开代理会报：

```
Protocol 'httpproxy' not on whitelist 'file,http,https,tcp,tls,crypto'!
...: Invalid argument
```

ffmpeg 把代理实现成独立协议 `httpproxy`，所以有代理时白名单要追加它。
`whitelist(proxy)` 就是干这个的，别写死字符串。

### 17. 超时要按代理速度放宽

弱节点上 ffprobe 打开一个 1.8 GB 的远程 MP4 要 **25~33 秒**，原来 25 秒的超时把它杀了，
而且 stderr 为空，最后只剩一句笼统的"ffprobe 打不开这个地址"——排查时极容易误判成 403。

现在 ffprobe 超时放到 90 秒、扩展侧 `helperCall` 150 秒。但 MP4 的正常路径已经不走 ffprobe 了，
只有非 MP4 或者头里找不到索引时才用。

### 18. 签名直链会过期

CDN 直链一般 `e=` 是过期时间戳。过期后所有请求 403，**重试没用**，只能回页面重新播放拿新链接。扩展列表里会显示 `HTTP 403`，别误判成"头没带对"。

---

### 19 列表卡片里的 `<video>` 多半是预览片

`preload="none"` + 挂在缩略图 CDN 下的几十 KB mp4，是 hover 时的动图预览，不是正片。
看到列表里一堆 `.mp4` 别高兴太早，先看域名和体积：正片通常在播放器域，几百 MB 起。

### 20 不带浏览器 UA 会被 CDN 直接 403

`curl` 默认自报 `curl/8.x`，很多视频 CDN 见它就 403，而且返回的是 html 错误页（几百字节）。
`curlRange()` 里统一兜底 `DEFAULT_UA` 就是为了这个。**探测和校验两条路都必须带 UA**，只在一个地方带会得到"能解析但下不了"的怪现象。

### 21 Referer 有两种相反的极性

同一个直链，带 Referer 403、不带 206，是完全正常的 —— 有些站是**禁止外站引用**，而不是要求引用。
所以不要写死"带上 Referer 更安全"；`probeMedia()` 两种都试，把能过的写回 `media.headers`。

### 22 签名直链只活几小时

`e=` 是过期时间（常见 3~4 小时）。批量抓完别攒着过夜，**边解析边下**。
链接过期后所有请求 403，重试没用，只能重新解析。

### 23 播放器会反广告拦截

有些播放器配置里有 `blockAB=true`，检测到广告拦截就不给播。这解释了一类"要多点几次才播得出来"。
不用管它 —— 批量抓取不经过播放器，直接解配置。

### 24 aria2 是最后才落盘的，别按文件大小算进度

实测一个 13 MB 的下载：**整个 50 秒里输出文件一直是 0 字节**，`du` 只有 4 KB，结束时一次性变成 12.8 MB。
数据先在内存里攒着，所以 `watchOutput()` 那种"按文件大小算进度"对 aria2 任务必然全程 0%，
用户看到的就是"一直是 0%，显示 aria2/curl"。

现在 aria2 分支走 `trackAria2()`，直接读它自己打的进度行：

```
[#60ba5d 11MiB/12MiB(88%) CN:10 DL:129KiB ETA:12s]
```

配套两处：

- `watchOutput()` 发现 `job._aria2At`（最近 5 秒 aria2 报过进度）就让位，别拿 0 字节去覆盖；
- **卡死保护**：running 但 5 分钟一个字节都没收到就 kill 并标错，否则一个死链会霸占并发位，把后面整队堵死。
  默认 `VG_CONCURRENCY=2`，堵两个就全停了。

排队中的任务要在 UI 上写「排队中」，不能显示 `0%` —— 那不是进度，是还没轮到它。

### 25 aria2 报错时，真原因在页脚上面

失败任务的最后三行永远是：

```
aria2 will resume download if the transfer is restarted.
If there are any errors, then see the log file. See '-l' option in help/man page for details.
```

原来的 `job.error = job.lastLine` 取到的就是这句废话，用户只看到"请参阅日志文件"，看不出是 403 还是重名。

现在走 `helper/errors.mjs` 的 `extractAria2Error()`，从整段 `logTail` 里往回找：

1. `errorCode=(\d+)` 的那一行 + 下一条（通常带 `status=403`），再配上中文提示；
2. 退而求其次找 `[ERROR]` / `Exception:`；
3. 都没有才取最后一条非页脚的行。

顺手把 `URI=...` 打码，别把签名直链甩到界面上。

常见 `errorCode`：`13` 文件已存在（重名/残留）、`22` HTTP 状态不对（多半 403）、`3` 资源不存在、`19` DNS 失败。

### 26 0 字节残骸会让重下永远失败

上次失败的成品可能留在磁盘上：0 字节的 `xxx.mp4`，但 `.aria2` 控制文件已经被删掉了。
这时 aria2 带 `--continue=true --allow-overwrite=false` 会直接判 `errorCode=13 File already exists`，
重下多少次都一样。

`createJob()` 现在会先看一眼：文件存在、大小 0、且没有同名 `.aria2`，就删掉再下。
**非 0 字节的残留不删**（那可能是真的下了一半），撞上了要手动删。

### 27 批量里同名会把文件互相覆盖

名字取自网页标题，同一批里三个视频标题一样是很常见的。重名直接交给 aria2 会得到
`errorCode=13 File already exists`；更糟的是它可能拿新任务的响应去覆盖已经下好的文件
—— 实测一个 584 MB 的成品，同名任务失败后留下了 548 字节的错误页。

`createJob()` 现在落盘前用 `naming.mjs` 的 `uniqueName()` 自己分配名字，按 `名字 (1).mp4`、`(2)` 递增。
判"这个名字被占了"要看三处，漏一处就会撞：

1. `jobs` 里已登记的同路径任务 —— 同一秒创建时磁盘还是空的，只看文件系统会漏；
2. 磁盘上有同名 `.aria2` → 可续传，放行；
3. 磁盘上是别人的成品（非 0 字节、无控制文件）→ 换名保护。

同一个源地址重下仍然沿用原名，那属于续传，不该产生 `(1)`。

### 28 把代码拼进 HTML 用 `String.replace`，会被 `$&` 啃坏

`tools/shot.mjs` 要把 popup.js 整段塞进 HTML：`html.replace('</body>', '<script>' + code + ...)` 这样写，
脚本里的 `$&`、`` $` ``、`$'` 会被当成替换串里的分组引用展开，产物直接语法错误，页面只剩静态骨架
（表现就是"截图出来了但没数据"）。**替换串来自代码时一律用函数式替换**：

```js
html.replace('</body>', () => `<script>${code}</script></body>`);
```

另外两件配套的事：

- 无头 Chrome 每次要给独立 `--user-data-dir`，否则报 `Failed to create a unique user data directory`；
- 在受限沙箱里跑要加 `--no-sandbox --disable-crash-reporter`，不然起不来；
- 加 `--blink-settings=preferredColorScheme=1` 固定浅色。不加就跟着系统主题走，换台机器或改了深色模式，
  全部截图变色，README 里深浅混杂。
- **假 chrome 的 `default: return { ok: true }` 会把失败路径伪装成成功**：`helper:submit` 没写 case 时，
  「助手没开」的截图实际展示了成功分支（跳到任务面板），`helper-sheet.png` 和 `jobs.png` 一模一样
  却没人发现。新增状态截图时，先确认它点的那条消息有显式 case。

### 29 改数据形状要两端一起看：`/api/scan` 只认字符串链接

`helper/server.mjs` 的 `/api/scan` 用 `/^https?:/.test(String(x))` 过滤 `body.links` —— **只收字符串**。
扩展把 `collectPageLinks` 改成返回 `{url, label}` 对象后，`String({})` 是 `[object Object]`，
助手把整批链接丢光，退回静态 HTML（JS 渲染的列表页 HTML 里没条目），表现就是批量页永远
「这一页没认出条目列表」。而本地兜底只在助手**连不上**时才启动，助手正常返回空列表不会触发它。

教训：

- **跨进程传参的形状是接口的一部分**。扩展 ↔ 助手之间改数组元素结构，先看对面怎么收；
  现在两端都兼容字符串和对象，但扩展发出去的仍是纯字符串（保老版助手），标签在扩展侧回填。
- **测试要有真链路**。当时的测试把 `/api/scan` 整个 mock 掉了，链路中间的过滤逻辑没人看。
  现在 selftest 有一条"助手在线"用例，抓包断言发出去的 `links` 全是字符串。
- 没认出条目时提示要带数字（`读到 N 条链接，最多的一组只有 M 条`），不然分不清是没滚到底、
  还是分组规则不认，用户只能瞎猜。
