# 视频下载器 · 使用说明

**什么时候读**：改嗅探逻辑、改下载调度、动 aria2 / 助手接口、加新的下载后端、Chrome 升级后扩展失效。

---

## 架构与数据流

```
页面请求
  └─ webRequest.onBeforeSendHeaders ──► 暂存 Referer / UA / Cookie / Origin（按 requestId）
  └─ webRequest.onHeadersReceived ────► 认媒体类型 + Content-Length + Accept-Ranges
                                        └─► tabItems[tabId] ──► storage.session（防 SW 休眠丢数据）
                                                │
popup 读列表 ◄──────────────────────────────────┘
   │
   ├─ ⚡ aria2：background 组 options.header ──► aria2 JSON-RPC addUri
   ├─ ⬇ 浏览器：chrome.downloads（不支持自定义头，只适合没防盗链的）
   ├─ 解析：先请助手 fetch（能带 Referer），失败再扩展自己 fetch
   └─ 助手：POST /api/jobs ──► ffmpeg（HLS）或 aria2c（MP4），轮询 /api/jobs 看进度
```

三个存储位置：

| 位置 | 存什么 | 生命周期 |
|---|---|---|
| `tabItems`（内存 Map） | 当前标签页的媒体列表 | SW 休眠后靠 session 恢复 |
| `chrome.storage.session` | `tab:<tabId>` → {items, segCount} | 关浏览器即清 |
| `chrome.storage.local` | `settings`、`jobs`（aria2 gid 列表） | 长期 |

## 请求头从哪来（403 的关键）

顺序是 `onBeforeRequest → onBeforeSendHeaders → onHeadersReceived`，同一个 `requestId` 串起来：

1. `onBeforeSendHeaders` 里把四个头按 `requestId` 存进 `pending`；
2. `onHeadersReceived` 判出是媒体后，把 `pending` 里的头合并进条目；
3. `onCompleted` / `onErrorOccurred` 清掉 `pending`，并做容量截断（超 3000 条砍一半）。

**必须带 `extraHeaders`**：不写这个参数，Chrome 不会把 `Cookie`、`Referer` 交给监听器。

```js
chrome.webRequest.onBeforeSendHeaders.addListener(fn, { urls: ['<all_urls>'] }, ['requestHeaders', 'extraHeaders']);
chrome.webRequest.onHeadersReceived.addListener(fn, { urls: ['<all_urls>'] }, ['responseHeaders', 'extraHeaders']);
```

另外 `manifest` 的 `host_permissions` 必须是 `<all_urls>`，否则只有当前激活标签页的权限。

## aria2 接口约定

- 方法 `aria2.addUri`，参数顺序 **`[token, [url], options]`**（token 形如 `token:密钥`，没设密钥就是 `token:`）。
- `options.header` 是**字符串数组**：`['Referer: https://x/', 'Cookie: a=b', 'User-Agent: ...']`，不是对象。
- 多线程三件套：`max-connection-per-server`（-x）、`split`（-s）、`min-split-size`（-k）。
- 断点续传靠 `continue=true`，同时要写控制文件（默认同目录 `.aria2`），所以 `-o` 名字别乱改。
- 只支持 http/https/ftp，**不支持 m3u8**；HLS 必须走 ffmpeg。

`aria2InputText()` 生成的导出文件长这样，可直接 `aria2c -i 文件`：

```
https://cdn/x.mp4?sig=1
  dir=/Users/xx/Downloads
  out=x.mp4
  max-connection-per-server=16
  split=16
  header=Referer: https://site/watch
  header=Cookie: a=b
```

## 助手接口

只绑 `127.0.0.1:8765`（`VG_PORT` 可改）。无依赖，Node 18+ 直接跑。

| 方法 | 路径 | body / 返回 |
|---|---|---|
| GET | `/api/health` | `{ok, ffmpeg, aria2c, curl, ffmpegPath, defaultOut}` |
| POST | `/api/parse` | `{url, headers}` → `{status, text}`；解析播放列表用，能带 Referer |
| POST | `/api/jobs` | `{type:'hls'\|'mp4', url, name, headers, outDir}` → job |
| GET | `/api/jobs` | `{jobs:[...], running, queued}` |
| POST | `/api/jobs/:id/cancel` | 取消 |
| GET | `/api/jobs/:id/log` | ffmpeg/aria2c 输出尾部 |
| POST | `/api/probe` | `{url, headers, proxy}` → `{ok, media:{duration,width,height,videoCodec,audioCodec,size,source}}`；MP4 走头部解析，HLS 直接返回空（前端用播放列表） |

`headers` 对象字段固定为 `{referer, ua, origin, cookie}`，和扩展里的 item.headers 一致。

type 判断：

- `hls` → ffmpeg，参数固定在 `ffmpegArgs()`：
  `-protocol_whitelist file,http,https,tcp,tls,crypto -allowed_extensions ALL -allowed_segment_extensions ALL -extension_picky 0`，全部在 `-i` **之前**。
- `mp4` → 有 `aria2c` 用 aria2c（`-x16 -s16 -k1M --continue`），没有就 `curl -f -L -C -`。

进度：

- HLS 从 ffmpeg stderr 抓 `Duration:` 和 `time=` 算百分比；
- MP4 每 900ms stat 输出文件，跟 `Content-Length` 比；长度先 HEAD 探，失败再 `Range: bytes=0-0`。

并发上限 `VG_CONCURRENCY`（默认 2），超出排队。

## 测试

```bash
node tools/selftest.mjs     # 逻辑：54 项，假 chrome API 直接驱动 background.js
node tools/popup-test.mjs   # 渲染：jsdom + 合成脚本，23 项
node tools/cdp-test.mjs     # 真浏览器：需要 Chromium，见下面坑 1
```

`tools/selftest.mjs` 的做法值得记住：在 `import background.js` **之前** 给 `globalThis.chrome` 装一套假的，监听器就会被收集到本地变量，然后手工触发 `beforeSend` / `headers` 事件、用 `L.msg()` 发消息，就能在没有浏览器的情况下测完整链路。

`tools/popup-test.mjs` 把 `common.js` 的 `export ` 前缀去掉、把 `popup.js` 的 import 行去掉，拼成一段普通脚本，用 `window.eval` 跑进 jsdom。改 popup 的模块结构时记得同步这个拼接逻辑。

## 坑

### 1. 品牌版 Chrome 不能命令行侧载扩展

`--load-extension` 和 `--disable-extensions-except` 在 Google Chrome 137+ 被禁（日志会写 `not allowed in Google Chrome, ignoring`），headless 下扩展也不会注册。所以：

- 自测只能静态 + jsdom；
- 真浏览器验证要 `chrome://extensions` 手动「加载已解压」；
- 想用 `tools/cdp-test.mjs` 跑自动化，得装 Chromium / Chrome for Testing，不能用品牌版。

### 2. `extraHeaders` 漏了就拿不到 Cookie

只写 `['requestHeaders']` 时 `Cookie`、`Referer` 是空的，表现为"抓到了链接但 403"。改监听器时先查这个。

### 3. `.ts` 是双关

既可能是 TypeScript 源文件，也可能是 HLS 分片。`classify()` 里对 `.ts`/`.m4s` 要求 content-type 是 `video/mp2t`、`video/iso.segment`、`application/octet-stream` 或 `video/*`；命中不了就当普通文件忽略。别图省事只按后缀认。

### 4. 扩展自己的 fetch 设不了 Referer

`Referer` 是 forbidden header，SW 里 `fetch(url,{headers:{Referer}})` 会被静默丢掉。所以：

- 解析 m3u8 优先走助手的 `/api/parse`（助手是 Node，随便设头）；
- 助手不在线才退回扩展直连，此时对防盗链站点可能 403，UI 要给出"启动助手"的提示。

### 5. `chrome.downloads` 不支持自定义请求头

防盗链直链用浏览器下载必 403。`⬇` 按钮只适合没防护的资源；有防护的一律 `⚡` 或助手。

### 6. ffmpeg 的 `-headers` 用 `\r\n` 分隔

不是 `\n`。写成 `\n` 时 ffmpeg 只认第一行，后面的 Cookie 全丢。

### 7. `+faststart` 会让大文件结尾重写一遍

`-movflags +faststart` 要读完整个文件再写第二遍，1.3 GB 会白等几分钟。助手默认不开启，需要时设 `VG_FASTSTART=1`。

### 8. SW 会休眠，内存状态要落 session

`tabItems` 是内存 Map，MV3 的 service worker 几十秒没事件就被回收。所以每次新增条目都 debounce 写 `storage.session`，popup 读不到时从 session 恢复。别把状态只放内存。

### 9. 分片会刷屏

一集 HLS 有几百个 `.ts`，全列出来没法用。默认折叠，只记 `segCount`；设置里 `showSegments` 才显示。

### 10. Homebrew 从 ghcr 拉包在国内几乎停滞

`brew install aria2` 卡在下载时，换镜像：

```bash
export HOMEBREW_API_DOMAIN="https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles/api"
export HOMEBREW_BOTTLE_DOMAIN="https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles"
brew install aria2
```

### 11. HLS 专用参数喂给 MP4 会直接报错

`-allowed_extensions` / `-allowed_segment_extensions` / `-extension_picky` 是 HLS 解复用器的选项。
拿这套参数去开一个 `.mp4`，ffmpeg 会报 `Option not found`，整条命令失败。

所以助手的探针按 URL 猜类型，先试不带 HLS 参数的一轮，失败再换另一套；两套都试不通才报错。
`inputOpts(headers, hls)` 的第二个参数就是干这个的，别写死。

### 12. 详情不做缩略图，只读文件头

最初做过"ffmpeg 抓一帧当缩略图"，实测走代理要 41 秒，删掉了。原因不在数据量——
把 `-probesize` 压到 32 KB，ffprobe 还要 25 秒，它在这条链路上会来回请求十几次。

现在 MP4 走自解析：`curl -r 0-262143` 取开头 256 KB（一次请求，约 2 秒），
自己 walk box：`ftyp → moov → mvhd` 拿时长、`trak → tkhd` 拿宽高、`stbl → stsd` 拿编码。
实测 41 秒 → **4 秒**。

两个关键实现点：

- **box 可能比抓到的窗口还长**（moov 几 MB 很常见）。不能因为 `off + size > end` 就 return，
  要按可见部分继续 visit 和向下递归，否则只能看到 `ftyp`。
- **HLS 完全不联网**：时长 = `#EXTINF` 求和、清晰度来主播放列表，前端 `hls:parse` 已经有这些数据。

头里没有 moov（非 faststart）时，再取尾部 512 KB 找一次；再失败才退回 ffprobe（慢，但兜底）。

### 13. 扩展自己的 fetch 设不了 Referer

`Referer` 是 forbidden header，SW 里 `fetch(url,{headers:{Referer}})` 会被静默丢掉。所以解析播放列表
优先走助手的 `/api/parse`（Node 里随便设头），助手不在线才退回扩展直连，此时对防盗链站点可能 403。

### 14.5 删除文件的接口必须做双保险

`/api/file/delete` 能删磁盘文件，而助手对任何本机网页开放（CORS `*`），这是个现成的删文件漏洞。

两道闸：

1. **Origin 白名单**：带 `Origin` 且不是 `chrome-extension://` 开头的，一律 403。
   浏览器的 Origin 由浏览器写，网页伪造不了；curl 这类没有 Origin 的本地脚本放行。
2. **目录白名单**：`path.resolve` 后必须落在 `~/Desktop`、`~/Downloads`、`~/Movies` 之下，
   且带正常扩展名。`/etc/hosts` 这种会被直接拒。

顺带删掉同名的 `.aria2` 控制文件，否则下次下载会以为还有断点。

### 14.6 任务按钮按状态给，别一套到底

- `active/waiting` → 暂停、取消
- `paused` → 继续、取消
- `complete/error` → 删除文件、删除记录

"删除记录"只清 `chrome.storage.local` 里的 jobs 数组（aria2 侧再调 `removeDownloadResult`），
文件不动；"删除文件"先打助手接口再清记录。已完成的行加 `.done` 类，名称转灰、进度条转绿。

### 15. 签名链接可能绑定出口 IP，代理要一路到底

典型现象：**浏览器能播、能下，curl/ffmpeg 一律 403，但同一域名根路径返回 200。**
这不是防盗链头没带对，是签名里的 `s` 绑了请求时的出口 IP。

判定方法：同一条 URL、同一套头，只用 `curl -x http://127.0.0.1:7897` 加不加代理各试一次。
一个 206、一个 403，就实锤了。

后果：预览、aria2、ffmpeg 必须走**同一个**代理出口，否则永远 403；换节点后旧链接作废，
要回页面重新播放拿新链接。设置里的 `proxy` 字段就是分发给这三者的：aria2 用 `--all-proxy`，
ffmpeg/ffprobe 用 `http_proxy`/`https_proxy` 环境变量。

### 15.5 代理用「自动跟随系统」，不要写死地址

写死 `http://127.0.0.1:7897` 的问题：遇到能直连的站也会绕代理，白慢一截；用户关了代理软件，
aria2 还会往一个没人听的端口发请求。

现在 `proxyMode` 三档：`auto` / `off` / `manual`。`auto` 由助手读 `scutil --proxy` 拿
`HTTPEnable/HTTPProxy/HTTPPort`，再用 `nc -z` 确认端口真的在听，才返回地址。

两个细节：

- `scutil` 说开着、但代理软件已经退了 → 端口检测会把它判成 `system-http-dead`，按直连处理。
- 助手不在时 `auto` 退回手动地址（或空），保证 aria2 还能下能直连的站。

### 16. 走代理时 ffmpeg 需要 httpproxy 白名单

`-protocol_whitelist file,http,https,tcp,tls,crypto` 里没有 `httpproxy` 时，开代理会报：

```
Protocol 'httpproxy' not on whitelist 'file,http,https,tcp,tls,crypto'!
...: Invalid argument
```

ffmpeg 把代理实现成独立协议 `httpproxy`，所以有代理时白名单要追加它。
`whitelist(proxy)` 就是干这个的，别写死字符串。

### 17. 超时要按代理速度放宽

弱节点上 ffprobe 打开一个 1.8 GB 的远程 MP4 要 **25~33 秒**，原来 25 秒的超时把它杀了，
而且 stderr 为空，最后只剩一句笼统的"ffprobe 打不开这个地址"——排查时极容易误判成 403。

现在 ffprobe 超时放到 90 秒、扩展侧 `helperCall` 150 秒。但 MP4 的正常路径已经不走 ffprobe 了，
只有非 MP4 或者头里找不到索引时才用。

### 18. 签名直链会过期

CDN 直链一般 `e=` 是过期时间戳。过期后所有请求 403，**重试没用**，只能回页面重新播放拿新链接。扩展列表里会显示 `HTTP 403`，别误判成"头没带对"。

## 加一个新的下载后端

1. `common.js` 加参数生成函数（纯函数，方便单测）；
2. `background.js` 的 `handle()` 加 `case`，用 `send` 返回 `{ok:true,...}`；
3. `popup.js` 的 `opsHtml()` 加按钮、`onListClick()` 加分支；
4. `tools/selftest.mjs` 补断言，`tools/popup-test.mjs` 的假 `sendMessage` 补返回；
5. `README.md` 的排错表补一行。

## 回退

本项目是纯增量工具：扩展在 `chrome://extensions` 里点「移除」即可，助手 `Ctrl+C` 或 `launchctl unload` 停掉，不留系统改动。
